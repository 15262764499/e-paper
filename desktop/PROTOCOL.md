# Pulse v1 · CH340 串口协议

本协议服务于 Windows 负载灯效程序。**不是 STM32 ROM 烧录协议，也不兼容现有 BLE 图像/OTA 协议。** MCU 接入已于 2026-09-17 实现；编译和使用见 `../docs/MCU_BUILD_WINDOWS.md`。STOP/断流后选择停灯，NFC 临时覆盖保持优先。

## 1. 传输层

115200 baud，8 data bits，no parity，1 stop bit，无流控。电脑 TX 对 MCU PA10/USART1_RX，电脑 RX 对 MCU PA9/USART1_TX。RTS/DTR 正常通信时解除断言；不通过协议触发复位、擦除或烧录。

## 2. 数据帧

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 2 | 帧头 `50 4C`，ASCII `PL` |
| 2 | 1 | 版本 `01` |
| 3 | 1 | 消息类型 |
| 4 | 2 | 序号，uint16 little-endian |
| 6 | 1 | payload 字节数，0～32 |
| 7 | N | payload |
| 7+N | 2 | CRC16，little-endian |

CRC：CRC-16/CCITT-FALSE，poly=0x1021，init=0xFFFF，refin=false，refout=false，xorout=0。仅覆盖偏移 2 开始的 version/type/sequence/length/payload，**不包含帧头**。最短 9 字节、最长 41 字节。标准 CRC 检查值：ASCII `123456789` → `0x29B1`。

CRC、版本或长度错误的帧应丢弃，按字节继续寻找帧头。支持任意拆包/粘包。禁止按字符串结束符解释二进制数据。建议空闲超过 1 秒丢弃未完成的帧；不要动态分配无限大的缓冲区。

## 3. 命令

### HELLO `0x01`，payload 长度 0

请求连接。收到后回 `0x81`，同一序号，payload 为单字节状态码。成功为 `00`。HELLO **不能直接点亮灯，也不能启动烧录**。

电脑打开串口后每 1 秒发送一次 HELLO，收到合法成功应答才发送 SET。超过 3 秒未应答显示“固件未应答”，但继续握手；不自动降级发送其他格式。

### SET `0x02`，payload 长度 5

| payload 偏移 | 类型 | 说明 |
|---|---|---|
| 0 | uint8 | 指标：0=CPU，1=GPU，2=物理内存 |
| 1 | uint16 LE | 百分比×100，范围 0～10000（5000=50.00%） |
| 3 | uint8 | 总亮度 0～100 |
| 4 | uint8 | 动画速度×100，范围 50～200（100=1.0 倍） |

MCU 验证范围后保存最新目标，回 `0x82`、同序号、单字节状态码。SET 每 500 ms 发送一次；电脑已完成指数平滑，MCU 无需再做相同平滑。**收到下一包不得重置动画相位。** 可以仅在进入电脑模式时重置。

### STOP `0x03`，payload 长度 0

停止电脑灯效并清除电脑控制有效状态，回 `0x83`、同序号、单字节状态码。首版推荐停灯；如果固件保留本地模式，可恢复进入电脑模式前的本地灯效，但必须在产品中明确。

暂停、所选传感器无效时电脑每 500 ms 发 STOP；主动断开/退出时尽力发送一次 STOP，**不保证收到应答**。

### 应答状态

| 值 | 含义 |
|---|---|
| 0 | 成功，已接受命令 |
| 1 | 参数或 payload 长度错误 |
| 2 | 暂不可用（例如 NFC/OTA 占用） |
| 3 | 不支持该命令 |

非零应答时电脑停止流式 SET 并显示错误，需重新连接。只有版本、CRC、消息类型、待应答序号、payload 长度全都正确，且发出命令未超过 3 秒的应答才有效。成功 HELLO 代表协议就绪，ACK_SET 代表命令接受；**不证明实物灯已正确点亮**。

## 4. 灯效定义

- 使用 Q2～Q6（74HC595 输出号），Q1/Q7 关闭，Q0 未使用。
- 每颗对应 20%：第 q 颗覆盖比例 `clamp((value_percent - (q-2)*20)/20, 0, 1)`。
- 动画内部时间随真实时间累计：`animation_ms += delta_ms * speed / 100`。调速应改变累积速率，不跳相位。
- 每颗相位 `(animation_ms + 3000 - (q-2)*300) % 3000`。
- 相位 0～600 ms 二次曲线渐亮；600～1200 ms 二次曲线渐灭；1200～3000 ms 熄灭。
- 峰值按该段覆盖比例缩放。100% 负载时五颗保持峰值。
- Q2 最大 duty=80%，Q3～Q6=100%；再乘整体亮度/100。
- 推荐每 10 ms 重新计算一次 duty，使用现有 TIM1/SPI2 亮度输出驱动。

参考实现为 `pulse/effect.py`，可与固件做逐点对照。

## 5. 超时与并发

- MCU 在超过 **3 秒未收到合法 SET 或 STOP** 后必须清除电脑控制、停灯或恢复本地模式。HELLO 不应续期旧灯效。
- 中断或 DMA 接收进入有界环形缓冲区；解析不能依赖串口读取恰好返回一整帧。
- 墨水屏长时间等待期间也需要及时解析，建议把接收处理加入等待服务；不要在串口中断里执行耗时灯效或 Flash 操作。
- NFC 临时覆盖可以保留：接收并保存电脑目标，NFC 结束后恢复未过期目标。OTA 期间建议 STOP/返回 BUSY。
- USART1 的文本调试日志可以与二进制帧混合，但应避免字节级交错。Windows 解析器会跳过非帧数据。
- 端口断开重连后重新 HELLO。序号 uint16 回绕；不将序号当作认证或设备身份。本协议用于本机 USB 控制，无加密或设备认证。

## 6. 生成测试向量

固定向量（十六进制）：

```text
HELLO seq=1:             50 4C 01 01 01 00 00 D9 FA
SET seq=2 CPU=50%:       50 4C 01 02 02 00 05 00 88 13 50 64 E9 E4
HELLO_ACK seq=1 成功:    50 4C 01 81 01 00 01 00 B4 86
```

在 `desktop` 目录执行：

```powershell
.venv/Scripts/python.exe -c "from pulse.protocol import *; print(encode(HELLO,1).hex(' ')); print(encode(SET,2,metric_payload(0,50,80,100)).hex(' ')); print(encode(ACK_HELLO,1,b'\x00').hex(' '))"
```

固件建议先实现 HELLO，再用 SET 的 0/20/50/100% 边界对照预览。必须验证 CRC 错误、分包、非法参数、USB 拔出、连续更新不重启动画，以及正常通信不误复位。
